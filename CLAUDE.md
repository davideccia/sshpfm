# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`sshpfm` — a Wails (Go + Vue/TypeScript) desktop app for configuring and managing SSH local port forwards, using the 1Password SSH agent for key authentication when available and falling back to a standard `ssh-agent`.

## Commands

Prefer the `Makefile` targets; they carry the flags the raw commands need.

- `make dev` — live development (`wails dev`: Vite dev server + hot reload, Go rebuilds on change; browser dev build on http://localhost:34115)
- `make check` — `go vet ./...`, `go test ./...`, and the frontend type-check (`vue-tsc --noEmit`)
- `make build` — macOS universal `.app` (arm64 + x86_64) into `build/bin`, then ad-hoc codesigned
- `make build-mac-arm64` / `make build-mac-amd64` — single-arch macOS builds
- `make build-windows` — windows/amd64 with the NSIS installer; `make build-linux` — linux/amd64
- `make dmg` — package the macOS `.app` as `build/bin/sshpfm-<version>.dmg`
- `make appicon` — regenerate `build/appicon.png` from `brand/logo-icon.png`
- `make clean` — drop `build/bin` and `frontend/dist`

## Build configuration

| What | Where |
| --- | --- |
| App name, version, copyright, comments | `wails.json` (`info` block) — feeds the macOS plists and `build/windows/info.json` |
| macOS bundle metadata | `build/darwin/Info.plist`, `Info.dev.plist` (bundle ID `com.davideccia.sshpfm`, min system 10.15) |
| Windows metadata and installer | `build/windows/` |
| App icon | `build/appicon.png` — Wails derives `iconfile.icns` and `icon.ico` from it |
| Window size, theme, per-OS options | `main.go` |

`tools/appicon` renders the icon onto Apple's macOS grid (an 824×824 rounded square inside a 1024×1024 transparent canvas); run it through `make appicon` after changing the brand mark.

The macOS bundle is ad-hoc signed, not notarized: it runs locally with a stable identity, but a copy moved to another Mac needs right-click → Open or a Developer ID signature.

## Architecture

Wails v2 binds the methods on the `App` struct (`app.go`) to the frontend; TypeScript bindings are generated into `frontend/wailsjs/` — do not hand-edit that directory, it is regenerated by `wails dev`/`wails build`.

Go side:

- `store/` — SQLite (`modernc.org/sqlite`, pure Go, no cgo) persistence of `Connection` profiles at `<user config dir>/sshpfm/sshpfm.db`. Schema changes go through the `migrations` ladder tracked by `PRAGMA user_version`: append a step, never edit one that has shipped
- `internal/sshauth/` — agent discovery (`FindAgent` checks `SSHPFM_AGENT_SOCK`, then the 1Password socket, and `SSH_AUTH_SOCK` last, because on macOS it points at the launchd agent even when 1Password is installed) and `known_hosts` handling, including the typed `UnknownHostKeyError`/`ChangedHostKeyError` that drive the trust-on-first-use dialog
- `internal/vault/` — Argon2id key derivation and AES-256-GCM sealing, with no knowledge of connections or SQL
- `internal/tunnel/` — `Manager` owns one `tunnel` per connection id: dial, listen locally, pipe streams, keepalive, and push `Status` changes out through the callback `app.go` wires to the `tunnel:status` Wails event. `authMethods` offers the agent key first and the profile's stored password second (as both `password` and `keyboard-interactive`, since PAM servers advertise only the latter); a missing agent is fatal only when there is no password to fall back on

### Password storage

Optional per-connection SSH passwords are encrypted at rest. `vault.Derive` stretches the master password into 64 bytes: the first half is the AES key and never leaves memory, the second is the verifier stored in the `vault` table. The master password is asked for at every launch and gates the whole UI; losing it is unrecoverable by design, and `ResetVault` clears the vault and every `password_enc` while keeping the profiles.

Three rules hold this together:

- **The store owns the crypto.** `Store.Unlock` installs the key, and seal/open happen inside `store/`. No caller can write a plaintext password to SQL by accident.
- **`Password` is write-only, `HasPassword` is read-only.** `ListConnections` runs every profile through `Redacted()`, so no secret crosses the Wails bridge. `StartTunnel` is the one consumer of the decrypted value.
- **A nil `Password` on update means "leave it alone".** An empty string removes it. That is what lets the edit form show a blank password field without wiping the secret, and it relies on `undefined` being dropped by the bridge's `JSON.stringify`.

`app.go` records a startup failure in `initErr` instead of killing the process, so the window still opens and every binding fails with a readable message (`ready()`). Bindings that touch connection data use `unlocked()`, which adds the vault check on top. It also refuses edits to a connection whose tunnel is up, and refuses to open a browser at a tunnel that is down.

Frontend (`frontend/src`): `App.vue` holds the sidebar/detail layout and view mode, and renders `VaultGate` instead of them until `useVault` reports `unlocked`. `composables/` wrap the generated bindings (`useConnections`, `useTunnels` — the latter subscribes to `tunnel:status` — and `useVault`), `components/ui/` holds the primitives. No direct filesystem/network/SSH access from the frontend.

### Styling

Tailwind CSS v4 (via `@tailwindcss/vite`), utility classes in the template. Do not add component `<style>` blocks, CSS modules, or a UI library — there are none in the codebase, and a second styling system would fork the palette.

The design tokens live in one `@theme` block in `frontend/src/style.css` and generate the utilities the components use: the `bg-canvas`/`bg-hover` surfaces, text (`text-ink`, `text-ink-muted`, `text-ink-faint`), the purple accent, `danger`, and the per-state tunnel colours. Reach for a token before a raw Tailwind palette class (`bg-neutral-900`) or an arbitrary value — the exceptions are one-off geometry like `w-[300px]`.

**The UI is neumorphic (dark neumorphism).** Elevation comes entirely from a dual box-shadow — a dark shadow and a light highlight, faking a light source — on an element filled with the *same* background as its parent, not from the old border+lighter-surface-swap approach. That is why `border-line`/`border-line-strong`/`bg-surface`/`bg-raised` no longer exist as tokens: a bordered, differently-shaded panel reads as flat, not embossed. Live shadow tokens, all in `style.css`:

- `shadow-neu-out` / `shadow-neu-out-sm` — convex, resting state (buttons, dialogs, cards).
- `shadow-neu-in` / `shadow-neu-in-sm` — concave, for recessed elements (inputs, pressed buttons, the selected sidebar row, inline data chips).
- `shadow-neu-panel-edge` — a one-sided groove (top/bottom/right) that separates a same-colour region, such as the sidebar, from its neighbours without a hard line.

`--color-canvas` sits at `#1c1c20` rather than near-black on purpose: both the black shadow and the white highlight need visible headroom to blend into, which a background already close to pure black does not give them. A border survives only as a semantic signal, never a structural one — e.g. `border-danger` on a validation or alert message.

Four rules the tokens encode, all load-bearing:

- **Dark only.** `style.css` declares `color-scheme: dark` unconditionally, there is no light palette and no `dark:` variant anywhere. That is also why `main.go` pins the native chrome to dark, and why the neumorphic shadow pair uses tinted-black/tinted-white rather than the light-grey base a typical neumorphism reference palette assumes.
- **Accent contrast.** `accent` is the brand hue and never sits behind text (3.96:1). Filled buttons use `accent-strong`, purple text uses `accent-ink`. `danger` splits the same way.
- **One accent.** Purple only, except the semantic `state-*` colours for tunnel status.
- **Shape consistency.** Panels/dialogs use `rounded-2xl`, buttons/inputs use `rounded-xl`, inline data chips use `rounded-lg` — pick the radius by element category, not per component.

Icons come from `@phosphor-icons/vue`. The font is Lilex (a monospace face, used for both `--font-sans` and `--font-mono` — the app has one typeface end to end), self-hosted through `@fontsource-variable/lilex` — the app must render with no network.
